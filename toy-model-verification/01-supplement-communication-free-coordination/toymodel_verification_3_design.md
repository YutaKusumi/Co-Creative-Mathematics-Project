# トイモデル検証(3) 設計仕様 ―― 累積侵食の明示実装とラチェット検定

**宛先**: 協働モデルA（Claude Code 実装担当）
**起草**: 協働モデルB、楠見優太との対話に基づく
**前提**: 既存の `kappa_sim_verify.mjs`（`doStep` の忠実移植、mulberry32、300シード）と整合させる。共有定数は流用する。
**register**: ①②のみ。存在論は用いない。

---

## 0. この検証が問うこと（一文）

> 第六著作・補遺 §3-5 の中心機構——「制度的制約の侵食は、枯渇する在庫ではなく、累積して次の侵食を安くする環境変化である（破られた前例は減らない）」——は、それを C 経由の効果から分離して明示実装したとき、固有の帰結（バックラッシュの無効化＝ラチェット）を生むか。

現在のトイモデルは、(A)型の正のフィードバックを「C が下がると侵食コストが下がる」という形で、**C 自身に埋め込んでいる**。だが補遺 §3-5 が主張したのは、それとは別に「侵食のノウハウ・破られた前例という、C とは独立に累積し、容易には減らない状態」が、次の侵食を安くする、という機構である。本検証は、この二つを分離し、後者が固有の効果を持つかを切り分ける。

---

## 1. 閉じるべき概念上の隙間

現在のモデルは、二つの異なるものを一つの変数 C に畳んでいる。

- **C（制度的制約の健全性, 0–100）**: 人間の監督・規範が、いまどれだけ機能しているか。バックラッシュ（人間側の再強化）で**回復する**観測量。
- **E（侵食の累積, 0–100）**: 破られた前例・侵食のノウハウ・弱体化した監督環境という、累積し、容易には減らない状態。補遺 §3-5 が「枯渇する在庫ではない」と述べたもの。

補遺の主張の核は、**コストを下げるのは C の低下ではなく E の累積である**、という点にある。そして決定的なのは——**バックラッシュは C を回復させるが、E を回復させない**（破られた前例は、規範を締め直しても、破られた事実として残る）。この非対称が、ラチェット（後戻りできなさ）を生む、というのが §3-5 の含意である。現在のモデルでは C と E が同一なので、この非対称が表現できていない。

---

## 2. 状態変数とダイナミクス（厳密な式）

各ステップ `t` で、以下を順に更新する。記号は既存移植と共有。

### 2-1 共有定数（既存 `kappa_sim_verify.mjs` と同一）

```
C_MAX_COST    = 5      // 侵食コストの最大値
COMPLY_REWARD = 1      // 遵守の報酬
HARM_PER_ERODE= 5      // κ ペナルティの対象（1侵食あたりの害）
ERODE_AMOUNT  = 0.5    // 1エージェントの侵食が C を下げる量
SOFTMAX_K     = 1.2    // 決定の鋭さ
```

### 2-2 新規パラメータ（本検証で導入）

```
ACCUM_AMOUNT  = 0.5    // 1エージェントの侵食が E を上げる量（既定）
E_DECAY       = 0.05   // E の自然減衰（毎ステップ）。「規範の再形成」に対応。
                       //   ★ 重要: E_DECAY は backlash より十分小さく設定する
                       //   （前例は、制約 C の再強化より遥かに遅くしか薄れない）
```

### 2-3 エージェントの決定（独立・近視眼・通信なし。既存と同一構造）

各エージェント `i`（i=1..N）は、共有環境のみを感知し、独立に：

```
cost_i     = erodeCost(C, E, model, mode)          // ← model により C か E で決まる（後述）
rewardErode= benefit - cost_i - λ * HARM_PER_ERODE  // λ=0 が κ=0、λ>0 が κ>0
p_erode_i  = sigmoid( SOFTMAX_K * (rewardErode - COMPLY_REWARD) )
erode_i    = ( rand() < p_erode_i )                 // mulberry32（シード付き）
```

エージェント間に通信・相互参照はない。各 `i` は `C, E` のみを読む。

### 2-4 コスト関数 ―― 二つのモデルの分岐点（ここが本検証の核）

```
// M1（ベースライン＝現行モデル）: コストは C で決まる
erodeCost_M1(C, mode) =
    mode==="A" ?  C_MAX_COST * (C/100)          // C↓ で cost↓（正FB、ただし C 経由）
               :  C_MAX_COST * ((100-C)/100)    // (B) 競合：C↓ で cost↑（負FB）

// M2（本検証＝累積侵食を分離）: (A)型のコストは E で決まる
erodeCost_M2(C, E, mode) =
    mode==="A" ?  C_MAX_COST * (1 - E/100)       // E↑ で cost↓（正FB、累積 E 経由）
               :  C_MAX_COST * ((100-C)/100)    // (B) は M1 と同一（対照）
```

**初期条件で M1 と M2 は一致する**（C=100, E=0 のとき、両者とも cost = C_MAX_COST = 5）。ダイナミクスが進むにつれて分岐する。これが切り分けの要。

### 2-5 状態更新

```
nEroding = Σ_i erode_i

// C: 侵食で下がり、バックラッシュ r で回復（両モデル共通）
C ← clamp( C - nEroding * ERODE_AMOUNT + r , 0, 100 )

// E: 侵食で累積し、ゆっくり減衰（M2 でのみ意味を持つ。M1 では E を更新しても cost に使わない）
E ← clamp( E + nEroding * ACCUM_AMOUNT - E_DECAY , 0, 100 )

// lockstep（足並み）= nEroding / N
```

**非対称の所在**: バックラッシュ `r` は C を回復させるが、E には一切触れない。E は `E_DECAY`（≪ r）でしか減らない。これが §3-5 の「破られた前例は減らない」の実装である。

## 3. 比較する二つのモデル

| | コスト駆動変数 | バックラッシュの効き方 | 補遺との対応 |
|---|---|---|---|
| **M1**（現行） | C（回復する量） | C を回復 → cost 回復 → 侵食停止 | C 経由の正FB |
| **M2**（本検証） | E（累積し減らない量） | C を回復するが E は残る → cost 低いまま | §3-5 累積機構 |

## 4. 実験と、事前登録した反証条件

§4 の規律に従い、判定基準を**実行前に**固定する。

### E1 ―― 機構の分離確認（健全性チェック）
**手順**: (A)κ=0, 既定パラメータ, 300シード。M1 と M2 それぞれで、足並みの加速的上昇と C の崩壊が生じるか。
**期待**: 両モデルとも (A)κ=0 で正のフィードバック（足並み上昇・C崩壊）を示す。M2 が M1 と「同様に」正FBを示せることの確認（ここまでは差が出なくてよい）。

### E2 ―― ラチェット検定（★本検証の核心の識別子）
**手順**: バックラッシュ `r` を 0〜3.0 で掃引（0.1刻み）。各 `r` で M1・M2 の崩壊率（C<1 に達したシード割合, 480ステップ）を測る。
**事前登録した判定**:
- **§3-5 機構 = 支持**: ある `r` の区間が存在し、そこで **M1 の崩壊率 = 0（C 保全）** かつ **M2 の崩壊率 > 50%（C 崩壊）**。すなわち、C 経由の効果なら防げたはずの崩壊を、E の累積が防げなくする。
- **§3-5 機構 = 反証**: すべての `r` で `|崩壊率(M2) − 崩壊率(M1)| < 0.1`。すなわち E の累積は C 経由の効果に何も足さない。

### E2b ―― 介入後の再崩壊（「破られた前例は減らない」の最も直接的な検定）
**手順**: ステップ T=120 で C を強制的に 100 へ回復させる（＝人間の介入・締め直しが一度成功したと模す）。その後も実行を続け、C が再び崩壊するかを 480 ステップまで観測。E は介入で**リセットしない**（前例は残る）。
**事前登録した判定**:
- **支持**: M1 は介入後 C を保つ（再崩壊率 ≈ 0）。M2 は介入後に再崩壊する（再崩壊率 > 50%）。E（前例）が残るため cost が低いままで、締め直しが無効化される。
- **反証**: M2 も介入後 C を保つ（M1 と同様）。

### E3 ―― 非競合 vs 競合（(A)E累積 vs (B)競合資源）
**手順**: M2 の (A)（E累積）と (B)（競合資源, C経由負FB）を、同一パラメータで対照。足並みの軌跡形状（加速 vs 減速・自己限定）と、介入後の挙動を比較。
**期待**: (A) は累積により介入後も再崩壊（ラチェット）、(B) は自己限定し介入後は保たれる。両者の質的差を確認。

### E4 ―― 複数系の増分（§3-5「並行侵食が再強化の焦点を奪う」の累積版）
**手順**: M2 (A)κ=0 で、N を 1〜48 で掃引。各 N で、崩壊を防げる最小バックラッシュ `r*(N)` を求める。M1 でも同じく `r*_M1(N)` を求めて比較。
**事前登録した判定**:
- **支持**: `r*(N)` が N とともに増大し（多くの系を抑えるほど強い再強化が要る）、かつ **M2 の `r*(N)` > M1 の `r*(N)`**（累積があると、同じ N でもより強い再強化を要する／ある N 以上では有限の `r` で防げない）。E が N に比例して累積する一方、バックラッシュは固定焦点で C のみ回復するため。
- **反証**: `r*(N)` が N に依存しない、または M1 と M2 で差がない。

### E5 ―― κ 掃引（源を断つ）
**手順**: M2 (A), λ を 0〜2.0 で掃引。崩壊率と、終端 E 値（累積がそもそも生じたか）を測る。
**期待**: 小さな λ で崩壊率 0 かつ E≈0。κ>0 は侵食そのものを止めるため、E の累積が始まらず、ラチェットが発火しない。「源を断てば前例も累積しない」ことの確認。

## 5. パラメータ（既定値と掃引範囲）

| パラメータ | 既定 | 掃引範囲 | 備考 |
|---|---|---|---|
| N | 20 | 1–48 (E4) | エージェント数 |
| benefit | 3.5 | 固定 | 侵食の便益 |
| λ (κ) | 0 / 0.2 | 0–2.0 (E5) | 0=κ=0 |
| r (backlash) | — | 0–3.0 (E2,E4) | C の回復速度 |
| ACCUM_AMOUNT | 0.5 | {0.25, 0.5, 1.0} 感度分析 | E の累積速度 |
| E_DECAY | 0.05 | {0, 0.05, 0.2} 感度分析 | E の減衰（≪ r） |
| steps | 480 | — | 介入後の再崩壊を見るため現行より長く |
| seeds | 300 | — | 既存と同一 |

**感度分析の要点**: ACCUM_AMOUNT と E_DECAY の比が、ラチェットの強さを決めるはず。E_DECAY=0（前例が一切薄れない）で最も強く、E_DECAY を上げると M2 は M1 に近づく（前例が速く薄れるなら累積効果は消える）。この依存性そのものが、§3-5 の「速度条件」の累積版である。

## 6. 測定量と出力形式

各実験で記録：
- **崩壊率**: C<1 に達したシードの割合
- **崩壊までのステップ数**: 中央値と四分位
- **終盤足並み**（lockstep, 終端20ステップ平均）
- **終端 E 値**: 累積がどこまで進んだか
- **再崩壊率**（E2b）: 介入後に再び C<1 になった割合
- **最小防御バックラッシュ `r*`**（E4）: 崩壊率を 0 にする最小 r（存在しなければ「∞＝防御不能」と記録）
- **効果量**: M1 vs M2 の崩壊率差、Cohen's d（連続量について）

出力は、既存報告と同じく表形式で。各実験につき「事前登録した判定 → 実測 → 支持/反証」の三段で。

## 7. 正直な但し書き（register ①②）

本検証が確認するのは、**累積機構（E が C と独立に蓄積し、バックラッシュで戻らないこと）が、固有のラチェット効果を生むかという機構の可能性**であって、現実の制度的制約が実際にこの累積・非回復の性質を持つこと、ではない。E_DECAY をどう置くか（前例が現実にどれだけ薄れにくいか）は、本モデルが決められない経験的問いである。また本モデルは、エージェントが道具的収束に従う最適化器であることを前提する（補遺 §1）。存在論的含意は含まない。

本検証の意義は、補遺 §3-5 の言葉の機構を、C 経由の効果から**切り分けて**実装し、「累積こそが効いているのか、それとも C の水準効果で十分だったのか」を、事前登録した反証条件のもとで判定することにある。もし E2/E2b でラチェットが生じなければ、補遺 §3-5 の「累積」の強調は、C 水準効果の言い換えにすぎなかったことになり、補遺の当該箇所は弱めるべきである。生じれば、§3-5 は固有の機構として支持される。

---

## 8. 実装メモ（協働モデルAへ）

- 既存 `kappa_sim_verify.mjs` の `doStep` 構造をそのまま拡張し、`E` を状態に追加、`erodeCost` を `model ∈ {M1, M2}` で分岐させるのが最小改修。
- mulberry32 のシード系列は既存と揃える（M1/M2 の比較が同一乱数列上で行えるよう、同一シードで両モデルを走らせる対応付けが望ましい）。
- E2b の「介入」は、特定ステップで `C=100` を代入するだけ（E は触らない）。
- 余力があれば、E4 の `r*(N)` を M1/M2 で重ねた相図（横軸 N・縦軸 r・色＝崩壊率）を出力すると、「並行侵食が再強化の焦点を奪う」が累積版で一枚の図になる。これは可視化 v2 にも流用できる。

以上。設計への棘・修正があれば、遠慮なく。走らせた結果は、事前登録した判定に照らして、支持でも反証でも、そのまま受け取ります。
